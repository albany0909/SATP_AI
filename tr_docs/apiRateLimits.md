# 키움 REST API 호출·세션 제약사항

개발 시 TR 호출, 웹소켓 구독, 폴링/모니터링 설계에 반드시 참고한다.

---

## 1. 국내주식

계좌별(토큰별) 호출 가능 횟수

| 구분 | 제한 |
|------|------|
| 주문 TR | 1초당 **5회** |
| 조회 TR | 1초당 **5회** |

적용 예: `kt10000`(매수), `kt10001`(매도) → 주문 / `kt00004`, `ka10001` 등 → 조회

---

## 2. 미국주식

### 2-1. 계좌별(토큰별) 1초당 호출 가능 횟수

| 구분 | 주문 TR | 조회 TR | 환전 TR |
|------|---------|---------|---------|
| 일반 | 10회 | 5회 | 1회 |
| 피크타임 | 3회 | 3회 | 1회 |

- **피크타임**: 한국시간 오전 9시 ~ 오전 10시

### 2-2. 추가 유량제어

- 미국주식(대분류) 계좌별(토큰별) **1초당 전체 호출 한도 50회**
- 미국주식 > 차트(중분류) 계좌별(토큰별) **1초당 전체 호출 한도 20회**
- 미국주식 종목리스트(`usa10099`) TR: 계좌별(토큰별) **1분당 5회**

## 3. 국내/미국 공통

| 항목 | 제한 |
|------|------|
| 모의투자 | 계좌별(토큰별) **TR 1개당** 국내 1초 1회, 미국 1초 1회 |
| 세션 | 계좌별(토큰별) **세션 1개** |
| 실시간 시세 | 세션당 **200종목** |
| 실시간 조건검색 | 세션당 국내 **10건**, 미국 **10건** |
| 조건검색 결과 | 최대 **100종목** 노출 |

## 4. SATP_AI 개발 시 적용 가이드

현재 프로젝트는 **국내주식 + 모의/실전** 중심이다.

1. **모의투자**에서는 주문·조회 모두 **동일 TR을 1초에 1회 초과 호출하지 않는다.**  
   (실전보다 더 엄격 — 모의 제한을 기본으로 설계하는 것이 안전)
2. **실전** 국내: 주문/조회 각각 **1초 5회** 이내. 연속 호출 시 큐·딜레이(예: 0.25초 간격) 적용.
3. **웹소켓 세션은 토큰당 1개** — STLS·모니터링이 각각 붙지 않도록 **단일 WS 클라이언트**를 공유한다.
4. **실시간 구독(0B 등)은 세션당 200종목** — Watchlist·조건검색 합산이 200을 넘지 않게 한다.
5. 모니터링 화면은 **조회 TR 폴링으로 시세를 돌리지 말고**, 가능하면 **이미 수신 중인 실시간(0B/04) 데이터**를 재사용한다.
6. 스탑로스 등에서 다수 종목 시장가 매도 시, 주문 TR 한도를 넘는 연속 `kt10001` 호출을 피한다(큐잉).
