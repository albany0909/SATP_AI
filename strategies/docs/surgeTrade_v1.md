## 1. 개요

키움 `ka00198` 실시간종목조회순위의 **당일누적(qry_tp=4)** 을 보고, 날짜가 맞는 KOSPI200∪KOSDAQ150 안에서 전일 정규장 종가 대비 상승이며, 같은 이벤트의 최초 급등(+10% 이상, 확인된 이슈)인 종목만 모의로 매매한다. `ka10027` 가격급등 순위가 아니다.

기본값은 꺼져 있다. 스펙 `enabled` 와 `settings.stratLive.SRG01.enabled` 가 둘 다 true 이기 전에는 주문 스레드를 만들지 않는다. 이 저장소 변경은 그 스위치를 켜지 않는다.

## 2. 조회 탭과 알고리즘 탭

- **급등주** 조회 탭은 전략이 꺼져 있어도 남는다. 주문을 내지 않는다. 탭이 보이면 거래일에 ka00198 당일누적을 15분마다, 그리고 16:00~16:10 최종으로 모의 호스트에서만 저장한다. 수동 갱신은 같은 조회로 장외에도 ADHOC 을 남긴다.
- **실계좌**·**주도주** 조회 탭은 기본으로 숨긴다. 표 코드와 데이터는 지우지 않는다. `settings.deskMonitorTabs` 에 `acnt`, `leader` 를 다시 넣으면 돌아온다. `deskAlgTabs` 는 이 조회 탭을 숨기지 않는다.
- 매매창 아래 운영알고리즘과 전략 설명은 유효 가동인 알고리즘만 보여 준다. 꺼진 알고리즘 목록으로 대신 채우지 않는다. 보유·주문 표는 그대로다.
- RAM01·LDR01·RCS01 은 이 작업에서 켜지 않는다. RCS01 스펙은 이 브랜치에 없다.

이슈 태그는 확인된 짧은 문구만 종목명 옆에 보인다. 근거 URL·발표시각·이벤트 ID 는 상세에 남긴다. 테마로 원인을 만들지 않는다. 종목명 노란 배경은 **같은 이벤트 ID 의 최초 급등일** 이고, 확인된 이슈이며, 일간 등락이 10% 이상일 때만이다.

Open DART `list.json` 은 문서화된 공개 API 로 파싱만 연결했다. 이 실행에서는 호출하지 않았다. 공시 제목으로 태그를 만들지 않는다. 사람이 이벤트 ID·일자·태그·URL·발표시각을 넣어 검증에 통과해야 확인 상태가 된다. 검증 통과가 곧 자동 매수는 아니다.

## 4. 수익률

현재 보유 수량의 **실제 체결가 가중평균**(수수료는 현금에서만 빼고 평단에는 넣지 않음) 대비다. 추가매수 뒤 다시 계산한다. 최초 체결가는 보관만 하고 임계값에 쓰지 않는다.

- `>= +5%`, `>= +10%`, `<= -5%`, `<= -10%` 는 경계를 포함한다.
- 재매수·추가매수 후 손실 정리·익절은 0% 를 포함하지 않는다. 0% 는 아무 것도 하지 않는다.
- 비교 오차는 1e-6 퍼센트 포인트다.

## 5. 매수

1. 최초 100만 원: 15:18 이상, 15:30 미만. 15:18 이후 관측된 스냅만. 16:00 스냅은 쓸 수 없다. 수수료 0.15% 를 포함한 정수 수량. 1주 미만이면 주문하지 않는다. 사이클당 최초 1회.
2. 체결이 0이고 미체결도 없으면 다음 거래일 시초에만 폴백. 시가와 현재가가 모두 전일 정규 종가보다 높을 때만. 부분체결은 미매수가 아니다. 그 다음 날로 쫓지 않는다.
3. 최초 진입의 추가는 다음 거래일부터. +5% 에 100만, +10% 에 100만. +10% 로 바로 올라도 그날은 1단계만. 하루에 추가 단계는 1개.
4. -5% 로 1주만 남긴 뒤 수익률이 0% 위로 **넘어갈 때** 100만 원을 한 번 재매수한다. 이미 플러스인 동안 반복하지 않는다. 재매수는 단계 플래그를 지우지만 그날 이미 쓴 추가 횟수는 지우지 않는다. 재매수 직후 평단이 바뀌므로 같은 판단에서 추가를 이어서 내지 않는다. 재매수 체결이 반영된 다음 판단부터 추가를 본다. 당일 추가가 허용되는 것은 재매수 진입뿐이다.
5. -10% 전량 뒤에는 1주 재매수를 하지 않는다. 새 확인 이벤트가 있어야 다시 최초 진입을 본다.
6. 현금이 모자라면 줄여서 빌려 사지 않는다. 다른 전략 보유는 사지 않고, 매도 수량도 이 전략 수량을 넘지 않는다.

## 6. 매도

우선순위는 -10% 전량, 그 다음 -5% 또는 (추가가 끝난 뒤 0% 미만) 1주 남김, 그 다음 15:15~15:30 수익 전량이다.

1주만 있으면 1주 남김 매도의 수량은 0이며 주문을 내지 않는다. 수량 판단 전에 미체결과 잔고를 맞춘다. 브로커 잔고를 모르거나 전략 수량보다 적으면 주문하지 않는다.

익절은 보유 수익률이 0%보다 크고, 현재가가 당일 시가보다 낮고, 직전 관측가가 직전 20개 수정종가 평균 이상이며 현재가가 현재 평균(최근 19개 수정종가+현재가) 미만일 때 전량이다. 15:15 의 확정 종가는 쓰지 않는다. 손실이면 이 익절은 하지 않는다. 익절로 잔고가 0이 된 그날 같은 이벤트는 다시 사지 않는다.

## 7. 주문 형태

- 09:00~15:20 미만: `kt10000` 시장가 `trde_tp=3`
- 15:20~15:30 미만: 보통 지정가 `trde_tp=0`. 명세에 장마감 동시호가 전용 코드가 없다. `81`(장후 시간외)은 쓰지 않는다.
- 15:30 이후 정규장 주문 없음

## 8. 모의 경계

최종 주문 전에 모드가 paper 이고, 호스트가 설정된 모의 호스트이며 `mockapi.kiwoom.com` 을 포함하고, 실호스트와 다르며, 계정 환경이 paper 로 확인되고, 토큰이 있어야 한다. 하나라도 아니면 브로커를 호출하지 않는다. 조회 세션으로는 주문할 수 없다. 실전 호스트로 조회를 우회하지 않는다.

SRG01 청산은 손실 매도 텔레그램 승인을 기다리지 않는다. TPX01 명세의 승인 대기는 그대로다. 이 전략은 텔레그램을 보내지 않는다.
